## 为什么之前效果有差别

用户提供的本机聊天确实加载了 Skill，但先走 Python 匿名 API 和较长的固定查询，
候选很少。GitHub API 与 Reddit 部分请求被拒绝后，Codex 的原生工具主要用来
补读已有候选；候选覆盖没有充分扩展。重复读运行说明、检查实现及手动拼装报告
又增加了耗时。检索成功的文章多，不代表找到了值得关注的新东西。

Python 请求与 Codex GitHub 连接的认证和网络路径不同；已有响应缺少配额证据，
不能把所有 403 确定归因为限流或凭据。OpenAI 页面的非公开地址校验失败也不是
HTTP 403。更新保持访问限制和 TLS 校验，不通过关闭校验解决问题。

## 已改成的工作流

1. 读取运行说明一次，根据宽泛领域选择探索方向；优先使用可用的 Codex 工具。
2. 原平台收集与原生检索共同发现候选；候选不足时换查询、换可用渠道。
3. 阅读原文，比较已有资源；对选中项目沿实际链接读取至少一层有效关联。
4. 导入工具真正返回的材料，校验引用位置、内容哈希和取得时间。
5. 将比较资料与原始来源分开保存；证据未知就保留未知。
6. 保存结构化报告，以内置简报命令输出中文研究结果，重复运行沿用有效分析。

新增 `--native-search` 和 `--host-only` 交接，修复原生 GitHub JSON 形状识别，
支持关联图外已读比较材料的引用，增加明确的分析错误、历史领域保留、引用材料
变化检查和比较材料预算限制。普通 CLI 及原有发现、监控和通知能力保留。
人工使用 Skill 时不需要知道这些参数。

## 真实外部检索与最初失败

验证 Agent 只收到宽泛领域 AI，自行选方向并使用真实原生工具：6 个搜索查询，
25 次搜索/读取工具尝试，20 个候选，选中 3 项研究。原始材料取得时间为
2026-10-13 11:40:53 至 11:49:08（北京时间）；外部研究约 8 分 15 秒。

初次提交失败，未生成报告：适配器未识别工具在 `github.com` 仓库 URL 返回的
实际仓库 JSON，分析又引用了关联图外的比较材料。最初执行不能算端到端成功。
同轮上游社区请求遭遇代理 403，一份原始结果文件读取返回 404；保留这些缺口。
最初包含本地收尾的总耗时为 11 分 43 秒，超过当时 10 分钟目标。
新版明确在检索截止后停止新读取，本地报告生成与总耗时另行记录。

## 研究结果及边界

KVShareArena 是近期可见的评测资源；报告区分缓存管理与横向质量/成本评测，
明确方法专属代码、逐题输出未全部公开。SkillsBench 与 OriginBlame 是有用的
较旧资源，按 `hold` 暂存，不作为近 30 天新突破推送。三份报告都含用途、
实际材料限制与下一步验证，不将作者实验宣称视为独立复现。

原生工具的返回只能证明本轮取得了相应材料；没有独立证明作者身份、全球最早
记录、HTTP/DNS/TLS 状态或实验正确性。部分原生论文读取仅有文本，作者或版本
元数据不完整，报告继续标记未知。深度限制留下的链接仍待进一步阅读。

分数是文档和本地历史的启发式代理，没有验证它能衡量科学创新。
原生工具是否可用、连接权限和来源覆盖依赖具体 Codex 会话。
本轮没有额外付费 Provider API 调用，连接器费用未报告。
新版 Windows 实机、真实机器人发送和无人值守语义 Agent 调度尚未验证。

## 怎么更新

从仓库首页下载完整更新包，解压并双击 `Install-Windows.cmd`，然后打开本机
Codex 新会话，输入 `$last30days intelligence discover AI`。旧 Skill 会备份；
已可用的 Clash 配置、数据库和报告保留。云端不能代替你在 Windows 上执行安装。
